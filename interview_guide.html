1. The 60-Second Elevator Pitch

How to introduce the project when asked "Tell me about what you built":

"I built Lost & Found Hub, a community-powered recovery network for lost belongings and pets. Traditional lost-and-found websites are passive, static CRUD bulletin boards where posts quickly get buried. I wanted to design an active recovery system driven by what I call the 'Missing Trail'—an interactive timeline tracking an item from Lost → Spotted → Found → Matched → Verified → Handover → Returned.

Technically, it is built with React 18, Vite, and Tailwind CSS. It incorporates a multi-factor heuristic matching engine that scores candidate matches between lost and found items, a zero-knowledge private detail verification system to stop fraudulent claims, a community sighting submission tool, and full client-side state persistence. I deployed the production build to Vercel with custom Single Page Application routing rewrites."

4. Persistence Tier storage.js, LocalStorage, initialMockData.js Reliable client-side persistence with 22+ realistic seed reports pre-populated.

The Smart Matching Engine Heuristic (`matchingAlgorithm.js`)

The matching algorithm scores prospective matches using a multi-factor weighted formula:

Match Confidence Score = (Category × 0.30) + (Name/Brand × 0.35) + (Location × 0.20) + (Time × 0.15)
  • Category Match (30%): Strict ID equality comparison.
  • Name & Brand Tokenization (35%): Tokenizes strings, cleans stop words, and evaluates word-overlap similarity.
  • Geographic Proximity (20%): Matches city and measures coordinate distance between loss point and discovery site.
  • Temporal Proximity (15%): Verifies discovery date is on or after the loss timestamp within a reasonable window.

4. Top 12 Interview Questions & Master Answers

Why did you build this as a Single Page Application (SPA) instead of Next.js SSR?
"The core value of Lost & Found Hub lies in rapid client-side interactivity: multi-filter searching, interactive step wizards, real-time map pin plotting, and modal workflows. An SPA built with React 18 and Vite delivers an instant, app-like experience with zero full-page reloads. For public SEO indexing at high scale, I would migrate public report pages to Next.js SSG/SSR while keeping the interactive wizards and dashboard client-side."
How did you manage state without using Redux or Zustand?
"I evaluated project complexity and avoided introducing Redux boilerplate. Instead, I used React's native Context API paired with custom hooks, splitting state into 4 distinct domains: AuthContext, LostFoundContext, NotificationContext, and ThemeContext. This domain separation ensures that updates in notifications do not trigger wasteful re-renders across the item catalog."
How do you prevent fraudulent claims on valuable items like phones or jewelry?
"During report creation, the reporter enters a Private Verification Detail—a secret only the genuine owner knows (e.g., a specific lock screen photo, internal engraving, or unique scratch). This field is stored privately and never displayed on public item cards. To initiate a claim, the claimant must answer this challenge question. The system verifies the response before unlocking the Safe Handover Messenger."
How does image uploading work without an external cloud bucket like AWS S3?
"In the reporting wizards, I utilized the browser's native FileReader API. When a user selects a photo, it reads the file and converts it into a base64 Data URL. This allows instant image previews inside the multi-step form wizard and persists the image string inside LocalStorage, eliminating the immediate requirement for external storage infrastructure."
How did you solve SPA routing 404 errors when deploying on Vercel?
"In an SPA, routes like /explore or /item/:id exist purely in React Router memory. Direct page refreshes cause Vercel's edge server to look for a physical file and throw a 404. I resolved this by configuring a vercel.json file with URL rewrite rules: 
{ "rewrites": [ { "source": "/(.*)", "destination": "/index.html" } ] }
This redirects all incoming sub-route requests to index.html, allowing React Router to parse the path and mount the appropriate component."
How does the 7-step wizard handle validation and step gating?
"Each step in the wizard has its own validation schema defined in validators.js. The 'Next' button validates only the fields belonging to the current active step. If valid, the wizard updates composite form state and advances currentStep; if invalid, it sets field-level error messages and blocks navigation. Users can also freely navigate backward without losing entered data."
How is Dark Mode implemented and kept accessible?
"I implemented Dark Mode using Tailwind's class strategy in ThemeContext.jsx. On load, it checks LocalStorage or queries the user's OS preference via window.matchMedia('(prefers-color-scheme: dark)'). Toggling the theme adds or removes the dark class on the root <html> element. All components use semantic Tailwind classes like bg-white dark:bg-slate-900 to ensure high contrast and readable text."
If you had to scale this to 100,000 active users, what would your backend architecture look like?
"To transition from frontend simulation to high-scale production:
  1. Database: PostgreSQL with PostGIS extension for spatial radius queries (e.g., 'Find items reported found within 5km of this point').
  2. Authentication: OAuth 2.0 (Google/Apple) with stateless JWTs or sessions stored in Redis.
  3. File Storage: Cloudflare R2 / AWS S3 with pre-signed upload URLs and CDN caching.
  4. Real-time Engine: WebSockets / Socket.io for live meetup messaging and instant sighting push alerts.
  5. Async Worker Queue: BullMQ / Celery to offload heavy matching algorithm calculations in background jobs.
"
What was the most challenging technical hurdle in this project?
"The most complex challenge was managing the append-only event stream of the Missing Trail. A report is not a static record; sightings, matches, and verifications happen asynchronously. Designing LostFoundContext so that submitting a sighting adds an event node to the trail, updates the primary item's status, recalculates candidate matches, and dispatches in-app notifications without mutating state required structured functional updates."
How did you structure the project to be easy to evaluate for interviewers and reviewers?
"I implemented One-Click Quick Login buttons on the Login page (/login) so reviewers can instantly sign in as a regular user or an administrator without typing credentials. I also pre-seeded the application with 22+ realistic sample reports across all categories so the app feels alive immediately on first load."
